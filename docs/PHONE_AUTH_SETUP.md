# TAPZEN authentication

TAPZEN uses email and password authentication. No SMS, WhatsApp OTP, Twilio, or Meta WhatsApp Business Platform integration is required.

## Sign in

- `POST /api/auth/login` — validates an existing email/password account and returns a signed session token.
- `POST /api/auth/register` — creates a user and business workspace, then returns a signed session token.
- `GET /api/auth/me` — returns the authenticated user and memberships.

Passwords are hashed with bcrypt. Session tokens are signed with the server-side `JWT_SECRET` and are valid for seven days.

## Existing accounts and data safety

Existing user records, email addresses, password hashes, memberships, organizations, branches, profiles, devices, and analytics are retained. Users continue to sign in with their existing email and password. No account recreation or data deletion is required.

The previous phone-authentication migration is intentionally retained as a backward-compatible database change: it made email/password fields nullable and added an optional unique phone column. The application no longer uses phone numbers for authentication. Keeping the migration avoids a potentially destructive rollback on databases where it has already been applied.

## Render environment

Required authentication configuration:
- `JWT_SECRET` — generated by Render and kept private.
- `DATABASE_URL` — existing PostgreSQL connection string.

No Twilio or WhatsApp credentials are needed.
